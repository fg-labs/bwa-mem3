
Usage: bwa-mem3 shm [-d|-l|--help] [--meth] [-u INT] [-t INT] [idxbase]

Options:
  -d        destroy all indices in shared memory (matches bwa v1 behavior)
  -l        list indices in shared memory; a third column flags
            incomplete, missing or unusable entries
  --meth    stage a `bwa-mem3 index --meth` index — auto-appends
            `.meth` to <idxbase>, mirroring `mem --meth`
  -u INT    densify the staged SA sample table to sample-rate shift INT
            (in [0,6]) when it is denser than the on-disk rate. Trades a
            one-time staging cost + extra shared memory for faster SA
            resolution at `mem` time, WITHOUT rebuilding the on-disk
            index. e.g. `-u 2` stages a stride-4 table from a stock
            stride-8 (default) index. A value >= the disk rate is a
            no-op (warns). Output is byte-identical either way.
  -t, --threads INT
            worker threads for the -u densify pass (default 1). The
            per-sample walks are independent, so this scales near-
            linearly; has no effect unless -u actually densifies (a
            target denser than the on-disk rate).
  -h --help print this help and exit

Stage with no flags: `bwa-mem3 shm <idxbase>` loads the index into
POSIX shared memory; subsequent `bwa-mem3 mem <idxbase> ...` runs
auto-attach instead of re-reading from disk. For meth indices, pass
the same plain `<idxbase>` to all three commands plus `--meth` on
`index`, `shm`, and `mem` (the c2t suffix is auto-appended).

Footgun: if you re-build the index, run `bwa-mem3 shm -d` first.
There is no staleness check -- a stale segment will silently mis-align.

Interrupted stage: `shm -l` marks it `incomplete` and `mem` loads
       from disk; rerun `bwa-mem3 shm <idxbase>` to reclaim and restage.
       Stagers hold a named POSIX semaphore only for a few ms of
       registry update; if one is killed inside that window, later
       stages block, and `bwa-mem3 shm -d` unlinks the semaphore.

macOS: POSIX shm has implementation-defined per-segment caps; large
       indices may simply fail to stage. Prefer Linux for production.
Linux: /dev/shm defaults to ~50% of RAM on bare metal; in containers
       it is often much smaller and may need raising via --shm-size
       (Docker) or an emptyDir tmpfs (Kubernetes).
