# Regression scripts

`meth_index_output.sh` generates its own reference and SE/PE reads to check full/minimal methylation index layouts, output prefixes, EM-seq/bisulfite/TAPS alignment parity, ordinary alignment compatibility, safe forced replacement, metadata relocation, gzip/read-only sources, scratch precedence and failure cleanup. Set `BWA_MEM3` to the binary under test; it runs in both `make test` and the canonical CI methylation step.

End-to-end parity and invariant checks. `chr22_parity.sh`,
`version_banner.sh`, `arg_range_validation.sh` and `rescue_prune_identity.sh` run on every matrix
row (the last one's pruning and banding checks need a build with the SIMD filter, which every row's build has; its table row says why); the rest run on the canonical
`Linux x86_64 AVX2 (mimalloc)` configuration only, except that `mem_cli_basics.sh`,
`mem_io_cli.sh`, `mem_seed_cli.sh`, `mem_extend_cli.sh` and `mem_pair_cli.sh`
also run on the Linux ARM64 row, for the neon tier (see below). Of those, the canonical
matrix row runs the Makefile checks, which need its built tree, and
`bam_roundtrip.sh`, which reads the SAM `chr22_parity.sh` leaves there; the
`canonical-regressions` job, which builds the same binary the same way (same
runner, compiler, flags and compiler cache) alongside the matrix, runs the
others. The exceptions are the scripts wired to a job of
their own: `profile_slice_cpu.sh` runs from `profiling-build` (see below);
`host_floor_enforce.sh`, `stream_output_order.sh` and `short_read_smoke.sh` run from `rebuild-variants`,
which builds the canonical row's configuration (Linux x86_64, avx2, clang-19)
three more ways -- every opt-in debug macro on (rerunning `chr22_parity.sh`
against it), `TESTING_BUILD=1`, and `ASAN=1` (rerunning `header_parity.sh` and other
memory-safety checks against it, and the whole unit suite) -- in parallel with the matrix rather than at the end of the
canonical row; and the `ndebug_gate_lint*`, `debug_macro_flag_lint*`,
`calloc_interpose_flag_lint*`, `shell_lint*`, `regression_coverage_lint*`,
`readme_contract_lint*` and `rescue_docs_lint*` pairs need no binary at all and
run from `ndebug-gate-lint`, `debug-macro-flag-lint`, `calloc-interpose-flag-lint`,
`shell-lint`, `regression-coverage-lint`, `readme-contract-lint` and
`rescue-docs-lint` respectively. Each script:

- is self-contained (set -euo pipefail; explicit input contract — env vars for
  every script but the source-only lints, which instead take an optional
  positional directory so their self-tests can aim the same checks at a fixture
  tree, and `meth_oracle.sh`, which reads no input at all)
- emits `PASS:` on success and `FAIL:` on failure, and `SKIP:` where a check
  cannot run (a missing tool, a host with nothing to compare) — a skipped check
  is reported as skipped, never as a pass
- returns nonzero on failure

Where a script runs is also what backs its claim: unless a row says otherwise,
read that row's byte-identity or parity claim as holding on the canonical
configuration — Linux x86_64, AVX2 tier, mimalloc — whichever of the two jobs
above runs it. Seven rows say otherwise, and none is one of
the job-of-its-own cases above. `chr22_parity.sh` runs on every matrix row, so
its parity claim is not AVX2-specific. `all_tiers_parity.sh` does run on the
canonical configuration, but it drives the binary through each usable tier with
`BWAMEM3_FORCE_TIER`, so the tier is the one thing its claim deliberately does
not hold fixed. `mem_cli_basics.sh`, `mem_io_cli.sh`, `mem_seed_cli.sh`,
`mem_extend_cli.sh` and `mem_pair_cli.sh` sweep the tiers the same way (the shared `simd_sweep_tiers`
helper in `test/framework/`), from
`canonical-regressions` for avx2 and avx512bw and from the Linux ARM64 row for
neon, so their claims hold on each shipped tier (for `mem_pair_cli.sh`, the
rescue and FF checks; its option checks run once, under the first tier). (`version_banner.sh` runs everywhere too, but its row asserts no
parity or byte-identity, so nothing here scopes it.)

`meth_oracle.sh` is another env-free script that is not a lint, and it takes no
argument either. It wraps the `--meth` harness under `test/meth/`, whose inputs
are the gitignored fixtures CI copies in there, plus an optional `SAMTOOLS`

and mark the result, so it passes the environment through rather than reading
or pinning any of it. "Reads no environment" is a claim about each script
itself — which is also how `readme_contract_lint.sh` decides it — not about
everything it may go on to run.

`readme_contract_lint.sh` checks that block against the scripts themselves, so
a script that stops reading the environment without gaining a mention here
fails CI rather than going unnoticed.

One exception to "any binary will do": `profile_slice_cpu.sh` asserts on
`--profile` output, which a default build compiles out entirely, so it needs a
binary from `make STAGE_PROF=1`. It fails loudly rather than skipping if handed
one without `--profile`, and CI runs it from the `profiling-build` job.
